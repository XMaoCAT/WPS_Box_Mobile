# 最小可运行集结论

日期：2026-11-12

## 结果
用 849 MiB（去重后）的最小集成功启动 WPS Writer 并渲染出完整界面，
对比完整 rootfs 的 3.0 GiB，缩减到约 28%。

| 项目 | 体积 | 说明 |
|---|---|---|
| office6（含资源） | 799.0 MiB | 二进制 + 全部 .so + skins/res/mui/data |
| syslib（系统库） | 49.8 MiB | 59 个非 glibc 依赖 |
| **合计** | **848.8 MiB** | |
| 压缩后（实测 28%） | **约 238 MiB** | |

## 关键经验

### 1. 不能只复制 .so
第一版最小集只复制了 `*.so` 和三个二进制，结果报错：
    Loading UI XML file failed.
必须带上资源目录：`skins/ res/ resource/ mui/ data/ cfgs/ dicts/
document theme/ asso_template/ oa/`。

### 2. 不需要 proot / chroot
`wps` 的 RPATH 是 `$ORIGIN:$ORIGIN/addons/cef:$ORIGIN/addons/kcef`，
即相对自身路径定位。复制到任意目录后 `ldd` 零缺失，可直接执行。

### 3. glibc 必须用宿主的
rootfs 的 glibc 是 2.35，宿主是 2.41。若把 rootfs 的 libc 放进
LD_LIBRARY_PATH 会立刻破坏宿主所有程序（已踩过两次）。
因此 libc/libm/libdl/libpthread/librt/libstdc++/libgcc_s/ld.so 一律
从宿主取，只补其余 59 个库。

### 4. libpng12 的缺失是误报
rootfs 的 `libfreetype.so` 链接脚本引用 libpng12，但 WPS 实际使用
自带的 `libfreetype.so.6`，运行时从不加载 rootfs 那个版本。
静态分析报的缺失，实跑从不报错。

## 复现命令
    env DISPLAY=:11 HOME=/tmp/wpshome PATH=/usr/bin:/bin \
        XDG_RUNTIME_DIR=/tmp/xdg \
        LD_LIBRARY_PATH="/tmp/minimal/office6:/tmp/minimal/syslib" \
        QT_PLUGIN_PATH="/tmp/minimal/office6/qt/plugins" \
        /tmp/minimal/office6/wps
