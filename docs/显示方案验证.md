# 显示方案验证结论

日期：2026-11-12

## 验证结果：weston RDP 后端可用

命令：

    weston --backend=rdp-backend.so \
           --rdp-tls-cert=rdp.crt --rdp-tls-key=rdp.key

输出证据：

    Listening on [0.0.0.0]:3389          <- RDP 服务端已监听
    xserver listening on display :0      <- Xwayland 同时启动

## 关键发现

### 1. 必须提供 TLS 证书

不带证书直接报错：

    the RDP compositor requires keys and an optional certificate for
    RDP or TLS security (--rdp4-key or --rdp-tls-cert/--rdp-tls-key)
    fatal: failed to create compositor backend

生成方式：

    openssl req -x509 -newkey rsa:2048 -keyout rdp.key -out rdp.crt \
        -days 3650 -nodes -subj "/CN=wpsbox"

### 2. 用宿主的 weston，不要用 rootfs 的

rootfs 的 weston 9 与 glibc 存在 2.35/2.38 冲突。
宿主 weston 14.0.2 自带 rdp-backend.so，无此问题。
正式 APK 里两者都没有，需要随包分发 weston 及其库。

### 3. FreeRDP 版本差异需统一

weston 14.0.2（宿主）使用 FreeRDP 3.15.0，
而 rootfs 里带的是 FreeRDP 2.10.0 的服务端库。
正式打包时需选定一个版本并保证配套。

### 4. Xwayland 随 weston 自动启动

配置 `xwayland=true` 后，weston 会自行拉起 Xwayland 并监听
display :0，无需单独启动。这简化了显示栈。

### 5. headless 与 rdp 后端二选一

headless 后端不提供画面输出，仅用于本地渲染测试。
正式方案用 rdp 后端，既渲染又输出。

## 正式实现要点

1. 随包分发 weston（含 rdp-backend.so）及其依赖
2. 首次启动生成自签名 TLS 证书，存于应用私有目录
3. weston.ini 写 [rdp] 段，绑定 127.0.0.1 以免暴露到网络
4. WPS 通过 DISPLAY=:0 连接 Xwayland
5. Android 侧实现 RDP 客户端解码画面
