# 架构决策：免 proot / 免 chroot 直跑

日期：2026-11-11

## 背景
原计划用 proot 提供 chroot 环境。实测发现 proot 2.3.1 与 WPS 存在
ptrace 信号死锁（主进程卡 do_wait，子进程卡 rt_sigsuspend），Termux 版
proot 5.1 又依赖 bionic 的 libtalloc.so.2，无法在 glibc 环境运行。

## 关键发现
WPS 的 `wps` 二进制带 RPATH：
    Library rpath: [$ORIGIN:$ORIGIN/addons/cef:$ORIGIN/addons/kcef]

`$ORIGIN` 表示"相对可执行文件自身路径"。这意味着 WPS 自带库通过相对
路径定位，完全不依赖固定的文件系统布局。

## 验证
把 `/opt/kingsoft` 复制到任意目录 `/tmp/direct/kingsoft`，
在不使用 proot、不使用 chroot 的情况下：
- `ldd` 检查：零缺失库
- 实际启动：`WPS Writer` 主窗口成功出现（1600x1000）

## 决定
正式实现不使用 proot，不做 chroot。直接以绝对路径执行 WPS 二进制，
通过 LD_LIBRARY_PATH / QT_PLUGIN_PATH 补足搜索路径。

## 收益
1. 无 ptrace 开销（proot 有 2-10 倍系统调用惩罚）
2. 无 ptrace 死锁风险
3. CEF 与 ptrace 的冲突问题一并消失（可安全保留 CEF）
4. 不需要伪造 /proc、/dev
5. 大幅减少运行时复杂度

## 仍需解决
rootfs 里的系统库（/lib/aarch64-linux-gnu，1277 MiB）仍然需要，
因为 WPS 依赖 libstdc++、libgcc_s 等。这部分由 LD_LIBRARY_PATH 提供。
